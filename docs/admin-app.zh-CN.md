# 管理应用规范

> [English](admin-app.md) · 简体中文

> 版本：v4.3 · 2026-11-12
> 一个小而顺手的研发控制台：看板、主机、容器、任务、SSH、对话、日志。

---

## 1. 定位

- **用户**：1–10 人的研发团队，自己用，不对外。
- **假设**：使用者就是管理员；不需要审批、不需要角色切换。
- **目标**：从打开页面到跑起一个构建 ≤ 30 秒；从发现异常到 SSH 进去 ≤ 10 秒。

技术栈保持 Refine + React + Vite；不引入新的 UI 框架。所有图形为自绘 SVG，离线可用。

---

## 2. 信息架构（8 个页面）

| 页面 | 路径 | 作用 |
|---|---|---|
| 总览 | `/` | AI Agent 工作室、状态数字、上手步骤、最近活动 |
| 构建机 | `/builders` | 容器列表、创建、启停、SSH 信息 |
| 调度机 | `/scheduler` | 调度容器状态、队列、吞吐、配置摘要 |
| 配置 | `/profiles` | Agent Profile 与 API Profile 的维护、启停用 |
| 任务 | `/tasks` | 任务列表、提交、详情、事件时间线 |
| 终端 | `/terminal` | 选中构建机，完整 SSH / Shell |
| 对话 | `/chat` | 与调度机器人 / 构建机器人对话 |
| 日志 | `/logs` | 调度机与控制面的操作记录 |

删除页面：审批中心、五角色办公室、主机管理、工作流配置、调度开发台、审计权限页。

## 3. 机器人形象

用两个**可爱的机器人**替代原来的卡通人物。自绘 SVG，无外部图片。

### 3.1 构建机器人「夯台」

- 体态：圆角方头、短腿、橙色工装、头上一根扳手天线。
- 颜色：主 `#e08a2e`，深 `#a45a12`，屏幕脸 `#1f2430`，LED 青 `#5fe0c0`。
- 状态：
  - `working`：眼睛扫描线左右移动，手臂扳手上下摆，旁边冒出代码粒子。
  - `idle`：缓慢眨眼，天线微微发光。
  - `rest`：屏幕显示 `z z`，呼吸变慢。
  - `alert`：头顶红灯闪烁，眼睛变红。
  - `offline`：整体降饱和，屏幕变暗。

### 3.2 调度机器人「派令」

- 体态：更瘦的圆角身体、胸口一个时钟表盘、头顶悬浮小光环。
- 颜色：主 `#2f8f83`，深 `#1c5f57`，屏幕脸 `#16202a`，LED 金 `#f0c75e`。
- 状态动画与构建机器人一致，但时钟指针随状态加速/停止。

### 3.3 通用规则

- 形象只表达状态，不做装饰性随机动画。
- 同一页面中角色尺寸分三档：看板 96–128、卡片 44、列表 28–32。
- 所有动画使用 CSS，尊重 `prefers-reduced-motion`。

## 4. 页面细节

### 4.1 总览

- 全部内容按当前主机过滤。
- 顶部：在线构建机 / 运行中任务 / 排队任务 / 失败待处理，四项合成一条状态栏。
- 主区「AI Agent 工作室」：
  - 调度机卡片固定在上：机器人、状态、实例 ID、资源、能力标签、部署或查看调度台。
  - 连接线下方是构建机卡片：机器人、实例名、系统与资源、当前任务或空闲。
  - 末尾固定一张虚线卡片，直接新建构建机。
  - 根调度机上方是侧载区，用带动画的连接线连到调度机：「接入侧载」虚线卡片给局域网设备发一个 curl 令牌；
    已创建的侧载显示主机卡通、在线 / 离线状态、令牌后四位和权限标签，点开可看详情并删除。
  - 侧载只显示当前主机自己的，合并进来的下级主机的侧载不会出现在这里。
  - 主机已经是裸机构建机时，左侧不再显示空调度机卡片：整台主机只能承担一个角色，那张卡片只会引向一个
    会被拒绝的操作。此时只保留构建机卡片并居中显示。
- 右栏：
  - 开始使用：部署调度机 → 部署构建机 → 提交第一个任务，按实际状态显示完成 / 下一步。
  - 最近活动：控制面审计记录，最多 5 条。
- 无审批、无权限提示、无角色切换。

### 4.2 构建机

- 表格：名称、系统版本、状态、CPU/内存、当前任务、SSH、操作。
- 顶部筛选：系统版本、状态。
- 「新建构建机」打开侧边表单：
  1. 选择 Ubuntu 版本（四张卡片：20.04 / 22.04 / 24.04 / 26.04）。
  2. 资源档位：轻量 / 标准 / 重型，或「自定义」填 CPU（0.5–16 核）、内存（512–65536 MiB）、磁盘（8–1024 GiB）。
  3. 数量（1–4）；Agent 与 API 各占一行，都是下拉选择（不显示适配器）。
  4. 确认：显示镜像 digest、SSH 端口、资源合计。
- 详情页：
  - 基本信息、SSH 连接块（命令 + 复制 + 下载私钥）。
  - 资源曲线（简化为三个进度条）。
  - 卷与工作区。
  - 操作：启动、停止、重启、排空、删除（二次确认）。

### 4.3 调度机

- 卡片：运行时长、版本、队列长度、吞吐（任务/分钟）、失败率。
- 队列视图：按优先级分组，显示等待最久的 10 条。
- 配置摘要：并发上限、租约时长、重试次数、老化时间（只读，修改走环境变量/配置文件）。
- 操作：重启调度机（二次确认）。
- 部署调度机：只选 Agent 和 API；镜像与数据库由控制面配置（`PCS_SCHEDULER_IMAGE` / `PCS_SCHEDULER_DATABASE_URL`）或所选 Agent Profile 的 `artifact_image` 提供，不经过界面。
- 调度机卡片里的「配置」可以换 Agent、增删 API Profile；构建机详情页同样有「配置」。绑定写入控制面，实例重启后生效。

### 4.3.1 配置

- 两段：Agent Profile / API Profile，各用一张表；点击行编辑，右上角新建。
- Agent Profile：名称、角色（创建后不可改）、Agent 类型（Claude Code / Codex / 自定义）；版本自动取该 Agent 已注册的版本。
  已知类型自动带适配器、入口与参数；只有「自定义」才显示适配器、入口、参数、镜像、能力。
- 职责与提示词：描述（只用于面板识别）、系统提示词；后者由适配器拼进提示词，平台安全约束始终追加在后。
- 权限：逗号分隔的 tool_id；留空表示全部权限。最大轮次与超时由运行时强制执行。
- API Profile：名称、服务商（DeepSeek / Anthropic / OpenAI / 自定义）、Base URL、API Key、超时、启用。
  预置服务商自动填好地址、认证方式与 `secret://` 引用；只有「自定义」才显示类型、认证、egress 与引用。
- API Key 只在保存时提交一次：控制面转发给 Secret Store，PCS 不落库、不回显；列表、日志与审计里只有引用。
  编辑时留空表示不修改；Secret Store 未配置时控制面返回 503，可只填 `secret://` 引用。
- 列表行「启用」右侧的删除按钮会先弹确认框；仍被在线实例或 Agent 引用时控制面拒绝，需先到构建机 / 调度机详情的「配置 Agent」里解除（选「不使用 Agent」，或移除对应 API）；已移除部署、已删除主机留下的绑定会在下次删除时自动清理。
- 实例用哪个 API 由构建机 / 调度机的「配置」选择，不在 Agent Profile 里重复指定。
- 数据库只保存 `secret://` 引用与镜像 digest；密钥值只存在于 Secret Store 的文件里（0600）。

### 4.4 任务

- 列表：标题、类型、目标构建机、状态、耗时、创建时间。
- 筛选：状态、构建机、时间范围。
- 提交任务抽屉：
  - 任务描述、目标构建机、优先级。
  - 任务只交给 Agent 执行：目标构建机必须在线、已绑定 Agent，且声明支持 `task.build`；不满足时不可提交。
  - 不再填写 shell 命令或工作目录；自然语言描述以 `requirements.build.instruction` 下发，
    确定性 Shell 执行器遇到它直接失败（`AGENT_REQUIRED`），不会误当命令执行。
- 详情：
  - 状态时间线（QUEUED → ASSIGNED → RUNNING → SUCCEEDED，以及 `NEEDS_INPUT`、`WAITING_CHILDREN` 两种暂停）。
  - 实时日志（SSE / 轮询）。
  - 产物列表与下载。
  - 取消 / 重试。
- Agent 控制：
  - 等待决策的任务会显示 Agent 的问题和回答框；提交回答即继续执行，「放弃任务」则取消。
  - 执行信息卡片显示自主程度（`ask` / `edits` / `auto` / `full`）与归类结果
    （`completed`、`error`、`input_expired`、`interrupted_after_outward` 等）。
  - 拆分任务的父任务会列出子任务的状态与结果；子任务可以跳回父任务。
  - 失败的尝试会显示失败分类（确定性失败 / 外部操作后中断 / 限流 / 资源占用 / 暂时性错误）、
    同类失败在全集群出现过多少次，以及失败签名，让多台构建机上的同一故障读起来是一个问题。

### 4.5 终端（SSH 完整权限）

- 左侧：构建机列表（机器人头像 + 系统版本 + 状态）。
- 右侧：
  - 顶部连接块：`ssh root@<host> -p <port>`，复制按钮，「下载私钥」。
  - Web 终端：完整交互式命令输入，无白名单；支持历史、`Ctrl+C`。
  - 提示条：「这是构建机内的完整 Shell，等同于 SSH 登录。请谨慎执行破坏性命令。」
- 不显示「受控」「审计」等旧文案；真实 SSH 由使用者自己负责审计。

### 4.6 对话

- 左侧：调度机器人 / 各构建机器人。
- 右侧：对话流 + 输入框。
- 快捷话术：在做什么、最近失败、给我一条构建命令、查看磁盘。
- 回复来源标记：Agent / 确定性。
- 对话不是审批证据，纯研发沟通。

### 4.7 日志

- 一张表：时间、动作、对象、结果、详情；实时模式下来自控制面审计日志。
- 不设独立的「设置」页：连接目标由页面同源决定（`/api/scheduler`、`/api/pcs`），界面不填地址；
  左下角只显示「未连接 / 实时 / 连接失败」状态：没有接入主机时是「未连接」，不算失败；已经接入但同步出错才显示「连接失败」。点击立即重新同步。主机在左下角主机菜单里选择，Agent / API Profile 由控制面维护。
- 添加主机探测通过后自动启动 runtime（host-runtime），主机入网即可部署组件；启动失败会在弹窗里显示原因，可在主机行点「启动 runtime」重试。
- 主机页每台主机都有「设置」：修改显示名、SSH 地址 / 端口 / 用户，或换一把私钥（留空沿用现有密钥）；保存后立即重新探测。这里的私钥是**发起连接的一方**（管理机或 PCS）的私钥，远程主机只保存对应公钥到 `~/.ssh/authorized_keys`。

## 5. 交互约定

- 所有写操作有即时反馈（按钮 loading、toast）。
- 危险操作（删除构建机、重启调度机）必须二次确认；确认文本为实例名。
- 空状态给出下一步动作，不只显示「暂无数据」。
- 连接模式：打开页面即连接同源的 PCS 与调度机，没有演示数据；所有页面按选中的主机刷新，左下角显示连接状态。
- 响应式：≥ 1280 三列看板；≥ 960 两列；移动端单列。

## 6. 视觉规范

- 背景：浅色 `#f6f4ef` / 深色 `#14181f`；卡片白色/深灰，1px 边框，圆角 14。
- 主色：构建橙 `#e08a2e`；调度青 `#2f8f83`。
- 状态色：成功 `#2f9e6f`、警告 `#c8912f`、危险 `#c23b3b`、离线灰。
- 字体：系统 UI；代码 `ui-monospace`。
- 机器人不抢信息层级：卡片里信息优先，形象占左侧 44–56px。
